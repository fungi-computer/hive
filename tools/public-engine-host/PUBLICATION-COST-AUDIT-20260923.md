# Public host publication cost audit

The local two-client v3 fixture does not support a host-side projection shortcut. The host already selects authenticated, nonretired, matching pack/world recipients before calling `observationPayload()`, and builds that shared payload once per publication. Any retained projection therefore belongs in the session observation owner, where its input dependencies can be checked.

The measured projection dominates recipient encoding: in the same 40-publication run, projection build was p50 20 ms / p95 37 ms (max 41 ms), while socket encoding and send was p50 2 ms / p95 3 ms (max 4 ms). Eligibility selection was p50 0 ms / p95 0 ms (max 0 ms at local workerd timer resolution). Those are host wall-time samples; projection includes session observation work and is not an isolated measurement of any one engine operation. The next step is to profile that owner before choosing a reusable projection boundary.

The workload was `colony-framework-proof-256-100-v2`, driven to sequence 40 and restart-checked at sequence 41 with two live authenticated local workerd WebSocket clients. Across 40 delivered-publication samples, 38 had two eligible recipients and 2 had one; clients received 41 and 40 complete observation frames. The encoded-byte p50 was 363,958 bytes across recipients per publication. Eighty attempts with no eligible recipient were excluded from delivery distributions and counted separately; their eligibility scan was p50 0 ms / p95 0 ms (max 1 ms) over 157 socket candidates. This excludes empty-recipient attempts rather than treating them as zero-cost sends.

For warmed committed steps 20–39 (20 samples), SQL execution/read wall was p50 2 ms / p95 3 ms (max 5 ms). The Durable Object transaction API, timed through resolution after commit, was p50 50 ms / p95 68 ms (max 83 ms). One alarm set was issued per step; its measured local API duration was p50 0 ms / p95 0 ms (max 1 ms). Alarm lateness was p50 0 ms / p95 1 ms. The cold first 20 steps are excluded from warmed quantiles; they contain startup and a transaction outlier. These are local workerd costs, not Cloudflare hosted SQL billing or service measurements.

The proof was based on source `9a4c525067ae1fd70e337df4eff8dc7598b99299`, with the dirty-tree proof harness and cost ledger instrumentation in this change; implementation hash `82442e9540d05117e06f3cd44f93a3fd4116c03ca456dd09756ddc13327a9e6b`. Result and local storage artifacts are retained in the ignored worktree path `.botanical/publication-cost-baseline-final-9a4c5250/RESULT.json`. The WebSocket harness extension supports `--clients 0..4`; the proof passed with `--clients 2` and verified both connected clients received observations and that autonomous restart advanced the already running world.

The host ledger now reports durable transaction and alarm API wall time, recipient eligibility, and zero-recipient skips as a separate series. A zero-duration alarm API value is a measured value at millisecond report precision, not an omitted/unmeasured field. Fallow is unavailable in the current shell/tool catalog, so there is no new Fallow result for the touched host files; no source hotspot advisory is suppressed by this audit.
