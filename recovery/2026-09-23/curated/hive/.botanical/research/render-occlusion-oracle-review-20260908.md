# Occlusion oracle review

**Valid positive witness:** freeze one camera, viewport, pose and world placement. Render A alone, B alone, then both. Let `shared` contain pixels opaque in both independent masks. If reliably depth-resolved combined pixels within `shared` include both A and B, neither whole-sprite order reproduces that sampled geometry visibility. That identifies a need for parts/depth representation or a deliberate visual compromise. An AABB cannot decide this case.

**Depth ties need an actual control.** Three’s installed `Material.js:210` defaults to `LessEqualDepth`. Its opaque render list sorts by group/render order, material, depth and identity: reversing scene children does not reliably reverse draw order. Repeat the combined pass with explicitly reversed per-subject mesh `renderOrder`, retaining ordinary depth testing/writing. Exclude changed-owner pixels as order-sensitive, and report their count. Require both owners among the stable shared pixels before claiming geometric interleaving. This establishes robustness to that control, not an exact continuous-depth measurement below buffer precision.

**Preserve surface coverage.** Current `art/geometry.js:9` uses opaque front-sided Lambert meshes; replacing their lighting with opaque `MeshBasicMaterial` is appropriate. Preserve side/culling, transformed scale, visibility through ancestors, geometry groups/draw ranges and clipping. Do not use DoubleSide to fill holes. Assert the supported material assumptions; transparent, alpha-tested/textured, displaced or shader-deformed subjects need a separate coverage contract. Keep/restorable original material references: the real art builder shares cached materials across subjects.

**Make IDs unambiguous.** Use distinct opaque endpoint colors, transparent clear background, pixel ratio 1, antialiasing off, no tone mapping, fog, blending or postprocessing. Keep output color handling fixed. Validate that readback contains only expected IDs/background and classify by both alpha and ID; mixed/unknown pixels are inconclusive. Read every pass before clearing again and clear color/depth between passes. A diagnostic depth/ID render is not equivalent to the lit/outlined game art.

**Keep transforms identical across passes.** Do not reframe each isolated subject. Capture under the same orthographic camera and common viewport, with actual facing and fractional stair translation applied once. Avoid clipping the overlap region. Existing 80/112 sprite crops, distinct anchors, world pixel rounding and the added outline are separate downstream presentation effects; this oracle cannot certify them. Screen-rocked trees likewise require their actual transform or an explicit unrocked scope. Capture before `bake` disposes geometry; restore materials and dispose only diagnostic-owned resources.

**Report narrowly:** shared count, stable A/B counts, order-sensitive/unknown counts, camera/resolution, subject phases/transforms and source hashes. Both stable owners prove failure of whole-sprite ordering for those sampled interiors. One owner only means a compatible order exists at those samples; zero overlap is inconclusive. Neither proves every phase/facing, continuous visibility, actual Pixi parity, or game integration. No execution occurred in this review.
