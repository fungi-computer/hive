## How to extract a deep module without hiding a god object

Choose a small public contract whose implementation contains the difficult policy, not a thin file wrapper around an enormous caller. For example, a scene hit resolver accepts pointer, selected level, tool mode and current scene revision and returns a typed ground/entity/no-hit result. It should not require callers to reconstruct its sorting or padding rules. A support query returns support source/reason/path; callers should not reimplement its radius rules. A resource operation settles a concrete transfer/claim atomically; callers should not maintain another goods list.

Conversely, do not pass the whole mutable world into generic middleware with arbitrary callbacks and call that extensibility. Keep command discrimination/exhaustiveness explicit, make returned plans or intents immutable where appropriate, and let the existing owner commit them. Config can extend recipes over implemented behavior. A new behavior remains a reviewed typed handler.

Persistence is the correct boundary to validate restored relations, but do not copy every runtime predicate into a second independent implementation. Extract reusable pure predicates where source facts genuinely align; preserve context-specific errors and migration distinctions. There is no requirement that all live states and every historical schema share one validator function. Splitting `checkHerbs` into helpers that still repeat location/claim laws is not the desired extraction.

## Stop rules

Stop a proposed abstraction when it adds another mutable copy, a plugin/event layer without a second consumer, an all-world scan for a local render fix, or more policy assembly in callers than the old implementation. Return the specific unmet requirement to Delivery. Do not stall the whole slice while inventing a general framework.

Stop a refactor when source/caller responsibility is clear, the replaced branch is gone, focused laws and physical interaction evidence pass, and actual Fallow changes have a written disposition. A remaining long declarative UI component or flat exhaustive switch is not automatically a release blocker. A score reduction with unresolved duplicate ownership is not success.

Stop proof expansion when the exact changed behavior is established. The interrupted upstairs browser trace is preserved; none of these packets retroactively completes it. Each coherent repair can be committed and served on the same preview after short focused proof and asset parity under existing permission. Report what is actually playable and what remains proposed.
