System mutation during a phase has another important limit: the selected systems array has already been captured. A newly added system will not join that captured array even though initialization can run immediately; removing/disposal of a captured system does not edit the copied array. The source does not provide a transaction barrier guaranteeing that disposed systems cannot receive the remaining captured hooks. Entity additions likewise affect the live entity array. These are source observations, not reproduced upstream bug reports; a Hive design borrowing this pattern should explicitly restrict structural registration changes to a known boundary.

Removal is also not synonymous with destruction. EntityManager removes world membership/listeners and invokes entity removal lifecycle; it does not automatically call `onRemove` for every component. Component removal has its own path. Reusable runtime entities can retain their components. Hive must therefore distinguish disposing a Pixi/query observer, retiring a runtime entity representation and destroying a physical world object. Only the domain transition can decide salvage, cargo and outstanding claims.

## Scene and headless boundary

The ECS core imports several Scene/Engine references as types, and the [system-manager tests](https://github.com/excaliburjs/Excalibur/blob/4a23dd1674b1771a88bbbf9e7f20bcd772e264c4/src/spec/vitest/system-manager-spec.ts#L103) exercise `new World(null)` followed by direct manager calls. That demonstrates a narrow testable manager, not a supported complete server-side simulation host. `EntityManager.updateEntities` reads `scene.engine`; `World.update(Update)` invokes it. System timing uses `performance.now`, with optional scene stats fallback.

The actual [Scene](https://github.com/excaliburjs/Excalibur/blob/4a23dd1674b1771a88bbbf9e7f20bcd772e264c4/src/engine/scene.ts#L193) provisions actions, motion/collision, pointer, isometric and drawing systems, and initialization creates input/camera context. Its own Update and Draw call the corresponding World phases. The pinned [unit configuration](https://github.com/excaliburjs/Excalibur/blob/4a23dd1674b1771a88bbbf9e7f20bcd772e264c4/src/spec/vitest.config.unit.ts) uses Playwright Chromium, including when called headless. The [package exports](https://github.com/excaliburjs/Excalibur/blob/4a23dd1674b1771a88bbbf9e7f20bcd772e264c4/package.json#L14) expose the engine entry, not a separate ECS-only entrypoint. Tree shaking or a custom adapter may be possible, but no bundle-size, Node/DO compatibility or isolated ECS-host claim was tested here.

## Six ideas worth borrowing

1. **Explicit system phases with narrow ownership.** A named system should own a coherent calculation over eligible facts, not a large entity class with many optional methods. Keep Hive's current fixed-tick phase order and command admission before pause. Draw/render extraction reads the committed result; it cannot advance growth, release claims or settle process output. First consumer: the existing movement/activity/material boundary, with a documented order rather than arbitrary priority numbers spread across files.
2. **A real structural-change boundary.** A queued retire/remove intent can avoid invalidating iteration, but Hive should settle its affected references and quantities at a named domain boundary. Decide when additions and removals become observable and invalidate indexes after successful settlement. Do not copy immediate additions plus sometimes-deferred removal and call it an atomic transaction. No generic framework is needed before one actual entity/material migration uses the rule.
3. **Explicit disposable runtime resources.** A system/view adapter owns the subscriptions, query handles, draw objects and temporary buffers it creates and exposes one bounded release path. Removing that adapter does not erase durable jobs, items or processes. First consumer: render/query cache lifetime during reset/Continue or scene replacement, proving old callbacks no longer mutate the new display while authoritative state is preserved.
4. **Capability composition validated before instantiation.** A body can have movement/profile/support references independently of work, inventory or familiar personality. Content definitions select supported capabilities; definition validation checks dependencies and illegal cycles before spawning. This is the useful ECS idea for cat/human/pack-animal reuse. Avoid runtime constructor dependencies that implicitly create resources or an actor-specific policy tree.
5. **Runtime identity separated from persistent records.** A runtime component/handle may point to a stable Hive entity ID, definition revision or physical lot. Authoritative state remains plain, versioned data checked by schema plus relational laws. Views/Jotai derive from it. Class constructor names, process counters and object clones cannot replace Cairn-backed persistent identity, snapshot migration, resource custody or completion IDs.
6. **Measure each phase before choosing a representation.** Excalibur's per-hook timing is a useful model for exposing where time goes. Add bounded measurements for existing Hive candidate construction, matching, pathfinding, activity, save and render work under the same meaningful workload. Metrics never select authoritative behavior based on wall time. An ECS library or data-layout migration is justified only if it removes a measured bottleneck/duplication with a clear replaced path; phase labels alone do not make 100 actors fast.

These ideas fit Hive without replacing its existing simulation owner, libcolony optimizer, persistent command/job model, Jotai projections, XState gestures or original Three→bake→Pixi art. A storage chunk is not a separate ECS world: actors, jobs, cargo, routes and environmental interactions can span many chunks under one authority. Derived query partitions may follow locality while the authoritative ownership boundary remains explicit.

## Small adoption test and stop rule

Pick one current concrete extraction, such as runtime render/query lifetime or body capability validation. Name its authoritative source, narrow operations, commit/visibility boundary and removed duplicate branch. Demonstrate that reset/reload disposes only runtime observers, that paused drawing changes no simulation facts, and that the existing saved outcome remains identical. Use a short existing fixture with actual useful work; no all-system rewrite or giant artificial entity count.

Do not add Excalibur itself based on this study. No source here establishes it as a drop-in deterministic headless ECS, a persistent world model, a mod sandbox, an actor scheduler or a fix for Hive's current picking/occlusion defects. The immediate architecture gain is clearer system ownership, lifecycle and mutation contracts; query/data-structure adoption remains a separately measured decision.
