## Duplication and performance

Runtime clone groups are narrow: sprite event registration in `view.js` (two overlapping groups); IndexedDB save/replace transaction skeletons (two); transfer source validation (one); party-member admission (one); identity lists in save validation (one). Source review found the shared geometry/picking owner already owns hit facts, but duplicated event wiring must still dispatch its current target rather than captured IDs. A shared binder may own registration/disposal when the renderer next changes. Save/replace may share transaction mechanics while retaining distinct malformed-save replacement policy. No reason to redesign the entire persistence API during the transport cut.

The 60 script groups include retained preliminary/failure proofs and repeated browser setup/cleanup. Preserve the artifacts and scripts. A later short-proof helper can centralize lifecycle and error collection for active consumers; deleting history to improve this report is forbidden. The generated libcolony wrapper matches upstream `--post-js` input by design; do not edit upstream or its generated output to reduce clones. Original art composition should split useful reusable geometry, not every mesh statement.

`workDirty` already prevents unconditional assignment every tick and the optimizer remains joint. However, `assignWork` calls `jobOption` (including paths) **before** checking work preference and the ready-offer limit in its inner worker loop. A cap on offered matches is not a cap on candidate/path computation. The future scale measurement must count actor/job/source candidates and path queries separately; narrow capability/scope/source eligibility before expensive routes, then measure again. Current array scans are acceptable for the tiny clearing, not evidence for 100 actors. Add canonical-owner indexes only for measured queries, with paused-command and load/reset invalidation. No new ECS or navigation provider is justified by this audit alone.
